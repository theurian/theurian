## The instrument, and why it is not `git grep`

Every key runs on **wrap-joined, whitespace-collapsed blocks**, and the
difference is not cosmetic. The key is the
[WatchDog ruling's](https://github.com/theurian/theurian/issues/199#issuecomment-5477040331)
own object key, pasted rather than described because a count is only readable
beside the thing that produced it:

```sh
git grep -inP '(nothing|nobody|none|no one|no code|no module)[^.]{0,80}reads?[^.]{0,80}(theurian/config\.yaml|(this|that|the) (config(uration)? )?file)' \
    -- '*.md' '*.py' '*.json' '*.yaml' '*.yml' '*.toml' \
       ':!.theurian/' ':!docs/work-logs/' ':!tools/audit/'
```

Run two ways over that one scope — the six suffixes the instrument reads, minus
the three excluded prefixes, so neither side is given a scope the other does not
have:

| Pass | Result |
| :-- | --: |
| line-oriented (`git grep -inP`) | **19** lines |
| wrap-aware (this instrument) | **31** sentences |

Those 19 lines land inside **17** of the 31 sentences, because two sentences
carry a matching line twice over
(`test_raptor_config_claims.py:576` on lines 581 and 582, and `:1797` on 1799
and 1802). So **14** sentences are ones a line pass never returns at all: no
single source line inside the sentence's own span matches the key, and a reader
running `git grep` does not see them.

> **Corrected in round two, and the error is the one this page exists to warn
> about.** This paragraph said *twelve*, and named #461's shipped claim as one of
> them. Twelve was 31 − 19 — sentences minus **lines**, a subtraction across two
> instruments that do not count the same unit. The two double-counted lines are
> exactly the gap: 31 − 17 = 14, and 19 − 17 = 2.
>
> The named example was wrong in the other direction. A line pass *does* return
> the #461 member whole — `ingest.md:34` reads "nothing reads that file today,
> so do not tell the user the allowlist is", and the key's `that file`
> alternative matches it on that one line. What is true about that member, and
> what the census actually depends on, is narrower: its **path** is on line 33
> and its claim on line 34, so the *path-keyed* form the census runs finds it
> only wrap-joined. Measured at `75c4c7a`, with the key's object half replaced
> by the path alone:
>
> ```sh
> git grep -inP '(nothing|nobody|none|no code|no module)[^.]{0,80}reads?[^.]{0,80}[\x60\x22]{0,2}\.?theurian/config\.yaml' \
>     -- '*.md' '*.py' '*.json' '*.yaml' ':!.theurian/' ':!docs/work-logs/' ':!tools/audit/'
> ```
>
> Restricted to `plugins/claude-code/commands/ingest.md` that exits 1 with no
> output; over the tree it returns 29 lines in 5 files. The zero is the key
> working rather than the key broken, which is the only thing that makes it
> readable.

**The scope is half the measurement, so both scopes are stated.** The same key
over the *whole* tracked tree returns 20 lines at the branch base `141cf6f` and
30 at `75c4c7a`, and nothing in the repository's claims changed in between: the
difference is this branch's own audit ledgers and this page, which quote the
sentences they classify. That is why the census excludes `tools/audit/` from its
own population, and why a number here without its scope beside it would be
unreadable within a day.

The governed population at the same commit: **485 files**, **64,982 sentences**.
What the instrument does not read, printed rather than assumed:
