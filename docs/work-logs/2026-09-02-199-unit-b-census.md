## The instrument, and why it is not `git grep`

Every key runs on **wrap-joined, whitespace-collapsed blocks**, and the
difference is not cosmetic. The WatchDog ruling's own object key, run two ways
over the same scope on this branch (`.theurian/`, `docs/work-logs/` and
`tools/audit/` excluded from both):

| Pass | Result |
| :-- | --: |
| line-oriented (`git grep -nP`) | **19** lines |
| wrap-aware (this instrument) | **31** sentences |

The twelve the line pass does not return whole are sentences typed across a
wrap, and #461's shipped claim — *"nothing reads that file today"*, whose object
is named one clause and one source line earlier — is one of them.

**The scope is half the measurement, so both scopes are stated.** The same key
over the *whole* tracked tree returns 20 lines at the branch base `141cf6f` and
30 at `f6e75fb`, and nothing in the repository's claims changed in between: the
difference is this branch's own audit ledgers and this page, which quote the
sentences they classify. That is why the census excludes `tools/audit/` from its
own population, and why a number here without its scope beside it would be
unreadable within a day.

The governed population at the same commit: **485 files**, **64,982 sentences**.
What the instrument does not read, printed rather than assumed:
`.sh` ×3, `.css`, `.html`, `.js`, `.lock`, `.png`, `.svg`, `.txt`, and 10 files
with no suffix at all.

### `ingest.md` — the #461 correction

The paragraph said a repository will have to be on the allowlist in
`.theurian/config.yaml`, then *"nothing reads that file today"*. The conclusion
it supports is right and the premise is not, so the premise was narrowed to the
fact that holds rather than the warning being dropped: the file has one reader
and one key in force, and **nothing reads `providers.review.repositories`** —
the #426 treatment.

Checked at the source before the record was trusted:
`git grep -nP "repositories" -- packages/theurian-core/src` finds no reader of
the allowlist key, and `infrastructure/github/__init__.py:12-19` already states
the same split in the same words.

**The corrected sentence produces no census row at all**, and that is the
correct outcome rather than a hole. The key admits a key object only through the
pronoun *"the key"*; this sentence names the key itself, which is the shape
`_referring`'s named-reference rule was written for. The regression direction is
what matters and it is still covered: any file-wide form returning to that
paragraph is an unrecorded suspect, exit 1, because `CONFIG_HOMES` and the
pronoun shape reach it without needing a path.

**The gap this correction leaves, stated rather than left silent.** The
fact side is held: `test_config_key_call_sites.py` scans the imported
`theurian` package for `WATCHED_SPELLINGS` and goes RED the day a reader for
`providers.review.repositories` lands, at which point this paragraph must move.
The prose side is held only *negatively* — the census reddens on a drift back to
the universal, but **no test asserts the corrected sentence's content**.
`SECRET_SCAN_PROSE_SURFACES` already carries an `ingest.md` row and pins one
sentence of it (*"stores no content"*); the row that would pin this paragraph
does not exist yet. It is owed, and it belongs to the tests specialist.

### ADR-0008 — the two #463 members

`4bfec1d` and `1cc2fa8` anchor dated line counts in two amendment blocks. Both
are real commits on branches that were squash-merged, so each resolved for
whoever wrote it and for nobody who cloned the repository.

**Repointing was tested, not assumed.** Each anchor names the working tree a
documentation pass started from, mid-branch, and no commit reachable from `main`
carries either tree:

```sh
git rev-list origin/main | while read c; do
    [ "$(git rev-parse "$c^{tree}")" = "$(git rev-parse 4bfec1d^{tree})" ] && echo "$c"
done          # -> no output; the same for 1cc2fa8
```

So each takes the pull-request qualifier and gains the reachable commit the work
landed as, which is the part a reader can check. Ancestry measured, not inferred
from the subject line: `c565c88..4bfec1d` is the branch that landed as `56582b2`
([#142](https://github.com/theurian/theurian/pull/142)), and `56582b2..1cc2fa8`
the branch that landed as `d1e79b1`
([#145](https://github.com/theurian/theurian/pull/145)).

Both tokens stay positive controls for `sha_anchors`, relabelled rather than
removed: the sentences were qualified, not deleted, so each is still an
unreachable sha sitting in governed prose and still exercises the reachability
half of the control. What no test holds is the *content* of the qualifier — a
sentence naming the wrong pull request would pass every audit here.
