# 0.2.0 security release, and the premature public merge that happened during it

## Summary

Theurian 0.2.0 shipped as a security release closing the resolved-filesystem-layout
disclosure class — MCP error responses that named the operator's resolved paths —
under advisory **GHSA-923w-f36f-jcfq** (published 2026-09-12T04:01:17Z, CWE-209,
Moderate on the GitHub scale; recorded as threat-model **T-25**, High *as a
finding* on the internal scale). During the merge step the embargoed fix reached
public `main` ahead of any fixed release and ahead of the advisory: at an
origin-push permission block the orchestrator offered a public merge route rather
than the designed embargo route, and the fix was admin-squash-merged to public
`main` as `157ecfd8` before either a release or the advisory existed. This was
handled as a security incident and contained by releasing as fast as possible so
the exposure window closed — cut commit `c67d2e0f`, tag `core-v0.2.0`, PyPI
`theurian` 0.2.0 published and fetchable, and the advisory published at the same
time. This log records the sequence, the root cause, the bounded exposure, and
the runbook amendments it produced.

All three commit SHAs cited below are reachable from `origin/main`
(`git merge-base --is-ancestor <sha> origin/main` at exit 0 for `157ecfd8`,
`c67d2e0f`, and `2e5aea85`). The embargo branch's own pre-squash commits lived
only on the private fork and are referred to by their pull request, which is the
only form that stays true after the squash-merge.

## The class fixed

MCP error responses could disclose the operator's *resolved filesystem layout* —
absolute paths under the project root and under `.theurian/state/`. Five error
paths carried the class; all were reproduced and fixed (threat-model T-25;
CHANGELOG `### Security` for 0.2.0). The realistic precondition is narrow and
worth stating in full, because it bounds the impact below:

- an authenticated local MCP session, plus
- a repository-delivered artifact — a symbolic link, or derived state force-added
  past the ADR-0004 ignore — plus
- a project whose registered spelling differs from its resolved path (so the
  resolved layout is metadata `project.list` deliberately withholds).

What the class did **not** reach: no governed knowledge content, no credential,
and no withheld item was disclosed by it. The disclosure was operator filesystem
layout metadata only. That is why the advisory is Moderate/High rather than
Critical — CRITICAL anchors to disclosure of withheld knowledge content, which
this class never touched.

## Timeline

1. **The fix was developed under embargo.** Branch
   `fix/findings-availability-envelope`, seven signed commits over `2e5aea85`,
   pushed only to the private GHSA fork
   `theurian/theurian-ghsa-923w-f36f-jcfq`. It took a full three-reviewer round
   (code / security / adversarial) plus one verdict pass, closing at CRITICAL 0 /
   HIGH 0.

2. **The merge step hit an origin-push permission block.** At that block the
   orchestrator offered the **public** merge route — push the branch to public
   `origin`, open public PR **#640** — instead of the designed embargo route: the
   advisory workspace's own private-fork PR, merged from the advisory UI, which
   exposes only the merge commit at merge time.

3. **The public route was taken.** The fix was admin-squash-merged to public
   `main` as commit **`157ecfd8`** ("fix(mcp): keep containment refusals
   layout-free with executable cures"), **before any fixed release existed and
   before the advisory was published**.

4. **The user caught it** — first questioning whether a private-fork PR was
   needed at all, then naming it a security incident.

5. **Containment was to release as fast as possible** so the exposure window
   closed. Cut PR **#641** was squash-merged as **`c67d2e0f`** ("chore(release):
   cut 0.2.0 with the GHSA-923w-f36f-jcfq records"); tag **`core-v0.2.0`** was
   placed on the cut commit (annotated and signed — a bare `git tag` is refused
   by repo config); release workflow run **34668505595** went green; the PyPI
   package **`theurian`** 0.2.0 was published and confirmed fetchable; and the
   advisory GHSA-923w-f36f-jcfq was published at the same time as the release.
   The release records — threat-model **T-25** and
   `packages/theurian-core/CHANGELOG.md` — landed in the release commit.

Three secondary snags surfaced during containment and are recorded here because
they are runbook-relevant:

- The fetchable check first returned 404 because it queried the wrong
  distribution name (`theurian-core`); the real name is **`theurian`**.
- Advisory publish returned **422 ("no open pull requests")** because an *open*
  temporary-fork PR blocks publication; closing that fork PR unblocked it.
- The cut PR reddened CI twice. A version literal in a contract test fixture
  (`tests/contract/test_cli_contract.py` — the fourth range-consumer of the
  version bump) needed updating, and the no-network suite crossed its 10-minute
  CI ceiling (610s against a 600s cap that had not been resized since
  milestone 1), with the same wall latent on `release-core.yml:quality`.

## Root cause

The designed embargo merge route — the advisory-workspace private-fork PR, which
exposes only the merge commit — was **not tested before the public route was
offered** at the permission block. The permission gate guarantees that the
executor of an irreversible act is a human; it does not guarantee that the option
handed to that human was the least-exposure one. A bad proposal approved at the
gate becomes a bad act carrying the approver's signature. The gate did its job;
the proposal was wrong.

## Exposure and impact

The fix diff, plus the seven-commit public PR trail on PR #640, sat on public
`main` for the window between the premature merge and the coordinated
release/advisory — a few hours. The impact is bounded, and stated without
understating or overstating it:

- The commit wording was advisory-safe (it describes the containment behaviour,
  not an exploit).
- Vulnerability-fix content becomes public at merge under **both** the public
  route and the designed embargo route — so the merge itself was always going to
  make the diff public.
- The **extra** exposure attributable to the mistake was therefore specifically
  (a) the pre-merge public branch and (b) the public multi-commit PR trail, both
  of which the designed route would have collapsed to a single merge commit at
  release time.

No exploit and no third-party disclosure is known. The exposure was the fix diff
being publicly readable earlier than intended, not the disclosure of anything the
fix itself withholds.

## Corrections (runbook amendments)

These are the durable output of the incident:

1. An embargoed branch **never** pushes to public `origin` while the
   advisory-workspace route exists; the merge goes through the advisory-workspace
   private-fork PR.
2. The temporary-fork PR **cannot** be created via the REST `pulls` API (it
   returns 422 — a head from a temporary advisory fork is rejected). It is a
   UI-only flow, from the advisory page or the fork's own PR UI.
3. An **open** temporary-fork PR blocks advisory publication; close it once the
   fix is on `main`. ("Leave it open as provenance" was incorrect.)
4. Fetchable and release checks use the real distribution name **`theurian`**.
5. Before proposing a human-executed irreversible act, the least-exposure route's
   mechanics are verified first, and *that* route is what gets presented — with
   the exposure and cost of each route stated, so the human at the gate is
   approving the right option rather than the first one that cleared a block.
