# T-26: the refusal timing measurements, and why they corroborate rather than prove

This is the durable home for the timing figures the T-26 closure cites (SEC-13,
T-17, 0.2.3). The threat-model entry
([`docs/security/threat-model.md`](../security/threat-model.md), T-26) now leads
with the **structural** proof of size-independence — by construction the refusal
path reads no body — and cites this log for the empirical **corroboration**. That
ordering is the point of this log too: the guarantee is the code and its pins;
the numbers below confirm it on one machine and do not stand in for it.

**Read the timing figures as dated, machine-specific claims, not invariants.**
They were taken **out of band and in process** — calling the store and gates
directly, with no loopback hop, no MCP framing, no JSON encoding — by the review
round's reviewers and the orchestrator while closing PR #712. There is **no
committed timing harness**; this is the same status the threat model records for
the T-22 accepted-cost figures ("In-process, and that caveat is load-bearing").
What *is* re-runnable by anyone, at the anchor below, is the structural guarantee:
the two pins in the last section, which I ran here and pasted GREEN.

## The channel, in one line

Three read gates — `knowledge.get`, `_relation_is_visible`,
`CanonicalVisibility._may_surface` — decide to withhold on `status`/`sensitivity`,
both columns of the `knowledge_items` pointer row. In 0.2.2 they reached the item
through `get_item`/`get_item_exact`, which `LEFT JOIN` the current revision and
materialise its **body** to recompute the GHSA-3f65 served-content hash. Refusing
a *withheld* item after that read made the refusal's wall-clock scale with the
withheld body's size, so a caller holding an item id could time the item's
existence and the approximate size of its content. 0.2.3 answers the gate from a
bodyless `get_item_metadata`/`get_item_exact_metadata` and reads the body only
once a row is surfaceable.

## Methodology — two corpora, interleaved

The comparison is **one operation against two stores that differ only in the
withheld row**:

- a store holding a withheld, **body-heavy** row (the row the caller times); and
- a store that **never held** that row (the absent/never-held control).

For the search face (`_may_surface`) the withheld row is a **T-17a-window row**:
surfaceable when the index that still ranks it was built, its canonical status now
`deprecated`, so the ranking gate re-checks it and refuses. That is the only face
whose withheld member can reach the gate through search rather than by explicit
id.

- Calls are **interleaved in a single session** so per-process warm-up and
  allocator state do not separate the two corpora on their own.
- Metric: **P = P(withheld-refusal time > absent/never-held median)** across the
  interleaved samples. `1.0` = the two are fully separable (the refusal time tells
  the withheld corpus from the control); `0.5` = indistinguishable.
- Worst instance: an **8 MiB** withheld body — `MAX_SOURCE_FILE_BYTES`
  (`security/paths.py`), the largest body a source file may carry — against a
  **256 B** body, so the size-independence claim is tested across the widest span
  the product admits.

## Results

Faces: **face-1** = `knowledge.get`, **face-2** = `_relation_is_visible`,
**face-3** = `CanonicalVisibility._may_surface` (the search ranking gate, timed on
the T-17a-window row).

### Pre-fix (`a5e7a11d`) — the channel is open

| Measure | Result |
| :-- | :-- |
| Separability P, all three faces | **1.0** (fully separable) |
| Body-scaled refusal delta at 8 MiB | **≈ +6.0–6.6 ms** |
| Adversarial positive control on the leaky face-3 code | **6794 µs vs 106 µs (~64×)** |

The positive control is the reason the post-fix collapse below reads as a fix and
not as a harness that measures nothing: on the pre-fix code the same instrument
separates the two corpora by ~64×.

### Post-fix (branch `5577491e`, PR #712) — the delta is size-independent

| Measure | Result |
| :-- | :-- |
| Refusal delta, face-1 / face-2 | **≈ +0.008 ms, identical at 256 B and 8 MiB** |
| Refusal delta, face-3 | **+0.009 … 0.036 ms**, size-independent |
| Position vs TB-1's 1.40 ms loopback floor | **~175× below** it (1.40 ms ÷ ~0.008 ms) |
| Separability P | **~0.4–0.55** — collapsed toward 0.5 |
| Orchestrator wire reproduction (`knowledge.get`, 2 MiB body) | **P 100% → 52%**, delta **+1.78 ms → +0.018 ms** |

The residual P sits **off centre (~0.4–0.55, not exactly 0.5)**, and that is
metadata-path jitter, not a body-size term: the pointer-row read still varies a
little run to run, but it varies the same amount whether the withheld body is
256 B or 8 MiB. It is acceptable precisely **because the gate now reads zero body
bytes** — there is no size term left for the jitter to carry. The wire
reproduction is the one figure taken across the loopback hop and MCP framing a
real client meets; it moves the delta from +1.78 ms (above TB-1's floor, and
readable) to +0.018 ms (below it).

**None of these numbers is the proof.** They confirm, on the machines they were
taken on, a property the next section establishes by construction and pins in the
repository.

## The durable guarantee: two in-repo pins, re-run here

Size-independence holds **by construction**: the refusal path answers the gate
from `get_item_metadata`, whose `_ITEM_METADATA_SQL` projects only
`knowledge_items` columns and joins no revision, so no body is on the row. A body
that is never read cannot make a refusal's timing scale with its size. This is
pinned **bidirectionally**, and unlike the timing figures these pins are
deterministic and run in the suite:

- **Run-time behaviour — the zero-body-read counters**
  (`tests/integration/test_pre_gate_body_materialization.py`): each withheld face
  materialises **zero** body bytes, while a surfaceable row still reads its body
  once (GHSA-3f65 preserved). RED before 0.2.3, when a body *was* read. Their
  blind spot is that they are **method-name-keyed** — they tally that the bodyless
  method was *called*, not that no bytes were read — so a `SELECT *` added the day
  `knowledge_items` grows a body column would leave them green.
- **Source fact — the explicit-column projection**
  (`tests/unit/test_gate_call_sites.py`, added on the fix branch, PR #712):
  reads the live `_ITEM_METADATA_SQL` constant and goes RED the moment it
  regresses to `SELECT *` or joins `knowledge_revisions` for a body, with a
  positive control asserting the *full* read still joins the body it needs for the
  GHSA-3f65 serve check. This closes the counters' blind spot.

*could* select one reddens the fact test. Re-run at the anchor above:

## Reproduction

- **The durable guarantee** reproduces deterministically: run the two pin files
  above at any checkout of the fix. To watch them bite — and to see the two
  instruments split — revert `_ITEM_METADATA_SQL` to `SELECT * FROM
  knowledge_items WHERE ...` in a throwaway worktree and run each file. The
  projection fact test goes RED; the method-keyed counters, run against the same
  drift, stay GREEN, which is the blind spot the projection pins exist to close.
  Demonstrated at the anchor above (throwaway detached worktree off the fix
  branch, PR #712, with `_ITEM_METADATA_SQL` reverted to `SELECT *`):

  ```
  $ uv run --frozen python -m pytest \
      packages/theurian-core/tests/unit/test_gate_call_sites.py -q
  ...
  FAILED test_the_metadata_read_projects_explicit_columns_never_a_star
  FAILED test_the_metadata_projection_is_exactly_the_columns_item_from_row_reads
  2 failed, 9 passed in 2.37s

  $ uv run --frozen python -m pytest \
      packages/theurian-core/tests/integration/test_pre_gate_body_materialization.py -q
  ..........                                                             [100%]
  10 passed in 4.87s
  ```

  The projection fact test names the direction the counters cannot see: a
  `SELECT *` reopens the channel the day `knowledge_items` grows a body column,
  and only the source-fact pin reddens on it.
- **The timing corroboration** reproduces in *shape* but not in *magnitude*: it is
  in-process and machine-specific, with no committed harness, so a re-run records
  a new anchor beside a new number. Its shape is the two-corpora comparison above:
  one operation, a withheld body-heavy row against a control that never held it,
  interleaved in one session, P over the refusal times, worst instance an 8 MiB
  body. On the fix, P collapses toward 0.5 and the delta is flat across the
  256 B → 8 MiB span; on `a5e7a11d`, P is 1.0 and the delta tracks the body size.
